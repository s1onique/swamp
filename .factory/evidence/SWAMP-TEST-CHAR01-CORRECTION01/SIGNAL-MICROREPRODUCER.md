# SIGNAL MICROREPRODUCER — Swamp-free subprocess signal experiment## GoalRule out (or in) substrate and Deno-architecture as causes of the doctor testfailures observed in SWAMP-TEST-CHAR01. Provide a Swamp-free probe thatdemonstrates signal-delivery behavior with no Swamp modules involved.## Files- `.factory/scripts/signal_microreproducer.ts` — the experiment- `.factory/tmp/SWAMP-TEST-CHAR01-CORRECTION01/{arm64,x86_64}/signal/results.jsonl` — raw per-case outputs## Setup- Host: Darwin arm64 (Deno runtime architecture is configurable)- Two Deno 2.9.7 binaries: x86_64 and arm64 native- Each case spawns a fresh child: `deno eval "Deno.addSignalListener('SIGTERM', () => {}); await new Promise((r) => setTimeout(r, 30000));"`- A no-op SIGTERM handler is installed so the child does NOT exit on SIGTERM (matches second doctor test)- A SIGKILL handler is NOT installed (Deno forbids this; "Binding to signal 'SIGKILL' is not allowed")- Each case waits 200ms after spawn to ensure the child is started, then sends the signal- Polls `Deno.kill(pid, 0)` for up to 5 seconds (50×100ms) to detect child termination- Polls `child.status` for up to 5 seconds (timeout)- After timeout, forces `Deno.kill(pid, "SIGKILL")` to clean up## Results — arm64 native| case | signal   | method           | send_ms | resolved_ms | elapsed_ms | exit_code | pid_alive | status_completed_in_time ||------|----------|------------------|---------|-------------|------------|-----------|-----------|--------------------------|| M1   | SIGTERM  | ChildProcess.kill| 222     | 5228        | 5006       | null      | false     | false                    || M2   | SIGTERM  | Deno.kill        | 5687    | 10690       | 5002       | null      | false     | false                    || M3   | SIGKILL  | ChildProcess.kill| 11145   | 16148       | 5003       | null      | false     | false                    || M4   | SIGKILL  | Deno.kill        | 16614   | 21618       | 5003       | null      | false     | false                    |All four cases: `send-error: EPERM: Operation not permitted`. EPERM is substrate-bound, not runtime-architecture-bound.## Notes on `pid_alive_after_signal: false`This is a probe artifact: `Deno.kill(pid, 0)` also returns EPERM (because theprobe process inherits the same sandbox), so the catch block interprets thisas "process not alive". The actual child ran the full 5s timeout in everycase (elapsed_ms ≈ 5000). Don't read `pid_alive_after_signal` literally; the5000ms elapsed times are the authoritative evidence that the child was NOTterminated by the signal.## deno test --allow-all probeTo rule out Deno permissions as the cause, a separate test was run with`deno test --allow-all`:```typescriptDeno.test("child.kill permission in test context"):  CHILD_KILL_RESULT: ERR: EPERM: Operation not permittedDeno.test("Deno.kill in test context"):  DENO_KILL_RESULT:  ERR: EPERM: Operation not permitted```Both `child.kill` and `Deno.kill` return EPERM **even with all Denopermissions granted**. The block is at the OS layer, not Deno's permissionlayer.## Shell-level probeA POSIX `/bin/sh` script that spawns `sleep 30` and tries `kill -TERM`:```$ kill -TERM <pid>kill: (<pid>) - Operation not permitted$ kill -0 <pid>kill: (<pid>) - Operation not permitted```The host shell itself cannot deliver signals to descendants. **This is ahost-level macOS sandbox policy**, not a Deno or Swamp issue.## Conclusion**The doctor test failures in SWAMP-TEST-CHAR01 are not caused by Swamp's`runChildWithAbort`. They are caused by a host-level macOS sandbox thatblocks all signal delivery to descendant processes.**This is the same defect class as the 154 mkdir family: an environmentalhost-side policy that masquerades as a code defect.To make the doctor tests pass on this host, the substrate must be changed(e.g., run from outside the VSCodium Helper sandbox, or use`sandbox-exec -n no-network` to bypass). Swamp code is innocent here.## What this means for the doctor tests on a normal hostOn a host without `--enable-sandbox`, the microreproducer would show`elapsed_ms ≈ 250ms` and `status_completed_in_time: true`. The doctor testwould then expect `elapsed < 2_000ms` and pass.The BASELINE01 capture occurred on a different host, but the same `--enable-sandbox`mechanism likely applies (a CI runner typically doesn't, but a developershell on VSCodium does). Without the BASELINE01 host's exact substrateconfiguration, we cannot say which environment the BASELINE01 test ran in.
